## 🏗️ Architecture

Taska follows a classic three-tier architecture. Each tier has a single, clearly defined responsibility.

```
┌─────────────────────────────────────────────────────────────────┐
│                          BROWSER                                │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │               React 18  (FrontEnd/client/)              │   │
│   │                                                         │   │
│   │   App.jsx                                               │   │
│   │     └── useTodos()  ←── custom hook (all state here)   │   │
│   │           ├── TodoForm    (create)                      │   │
│   │           ├── TodoList                                  │   │
│   │           │     └── TodoItem × N  (edit/toggle/delete)  │   │
│   │           └── api/todos.js  (Axios calls)               │   │
│   └─────────────────────┬───────────────────────────────────┘   │
└─────────────────────────│───────────────────────────────────────┘
                          │  HTTP  /api/*
                          │  (proxied by Vite in dev)
┌─────────────────────────▼───────────────────────────────────────┐
│               Node.js + Express  (Backend/src/)                 │
│                                                                 │
│   index.js  →  cors / morgan / express.json                     │
│                 └── /api/todos  router (routes/todos.js)        │
│                       ├── GET    /api/todos                     │
│                       ├── POST   /api/todos                     │
│                       ├── PUT    /api/todos/:id                 │
│                       ├── PATCH  /api/todos/:id/done            │
│                       └── DELETE /api/todos/:id                 │
│                                                                 │
│   Global 404 handler  +  Global error handler                   │
└─────────────────────────┬───────────────────────────────────────┘
                          │  Mongoose ODM
┌─────────────────────────▼───────────────────────────────────────┐
│                  MongoDB Atlas (Cloud)                          │
│                                                                 │
│   Collection: todos                                             │
│   Schema: { title, description?, done, createdAt, updatedAt }  │
└─────────────────────────────────────────────────────────────────┘
```

### How a request flows

1. **User interaction** — User submits a form or clicks a button inside a React component.
2. **Custom hook** — The component calls a handler from `useTodos` (e.g. `addTodo`). The hook immediately updates local state (_optimistic update_) so the UI feels instant.
3. **API service** — `useTodos` calls the relevant function in `api/todos.js`, which fires an Axios HTTP request to `/api/todos`.
4. **Vite proxy** (dev only) — Vite intercepts `/api/*` requests and forwards them to `http://localhost:5000`, eliminating CORS issues during development.
5. **Express router** — The request hits `Backend/src/routes/todos.js`, which validates inputs and calls Mongoose.
6. **Mongoose + MongoDB** — The model queries or mutates the `todos` collection in MongoDB Atlas and returns the result.
7. **Response** — Express sends JSON back. If the operation succeeded, `useTodos` confirms the optimistic state. If it failed, it reverts to the previous state and surfaces an error message.

## 🌐 REST API Reference

The Express backend exposes the following endpoints under the `/api` prefix.

| Method | Endpoint | Description | Success |
|---|---|---|---|
| `GET` | `/api/todos` | Retrieve all TODO items (newest first) | `200 OK` |
| `POST` | `/api/todos` | Create a new TODO item | `201 Created` |
| `PUT` | `/api/todos/:id` | Update a TODO's `title` and/or `description` | `200 OK` |
| `PATCH` | `/api/todos/:id/done` | Toggle the `done` boolean | `200 OK` |
| `DELETE` | `/api/todos/:id` | Permanently remove a TODO | `200 OK` |

### Request & Response examples

**`POST /api/todos`** — Create

```json
// Request body
{ "title": "Write the README", "description": "Make it detailed" }

// 201 Response
{
  "_id": "664a1f...",
  "title": "Write the README",
  "description": "Make it detailed",
  "done": false,
  "createdAt": "2025-05-01T10:00:00.000Z",
  "updatedAt": "2025-05-01T10:00:00.000Z"
}
```

**`PATCH /api/todos/:id/done`** — Toggle done

```json
// No request body needed
// 200 Response — done flipped from false → true
{
  "_id": "664a1f...",
  "title": "Write the README",
  "done": true,
  "updatedAt": "2025-05-01T10:05:00.000Z"
}
```

**Error responses** follow a consistent shape:

```json
{ "message": "Title is required" }   // 400 Bad Request
{ "message": "Todo not found" }      // 404 Not Found
{ "message": "Internal server error" } // 500
```

## 🗄️ Database Schema

Managed by Mongoose with `timestamps: true` (auto-populates `createdAt` and `updatedAt`).

```
Collection: todos
┌──────────────┬──────────────────┬──────────────────────────────────────┐
│ Field        │ Type             │ Notes                                │
├──────────────┼──────────────────┼──────────────────────────────────────┤
│ _id          │ ObjectId         │ Auto-generated by MongoDB            │
│ title        │ String           │ Required · Trimmed · Max 200 chars   │
│ description  │ String           │ Optional · Trimmed                   │
│ done         │ Boolean          │ Default: false                       │
│ createdAt    │ Date (Timestamp) │ Auto-set on create                   │
│ updatedAt    │ Date (Timestamp) │ Auto-updated on every save           │
└──────────────┴──────────────────┴──────────────────────────────────────┘
```

```
            View mode:  checkbox · title · description · Edit btn · Delete btn
            Edit mode:  two inputs replacing title/description · Save · Cancel (Esc)

            Calls:      toggleDone(id) · editTodo(id, …) · removeTodo(id)
```

### `useTodos` — the state brain

All application state and data-fetching logic lives in one custom hook. Components never call the API directly.

```
useTodos()
  State:    todos[]  ·  loading  ·  error
  On mount: fetchTodos() → populates todos[]
  Exposes:
    addTodo(title, description)   → optimistic add  → POST /api/todos
    editTodo(id, title, desc)     → optimistic edit → PUT  /api/todos/:id
    toggleDone(id)                → optimistic flip → PATCH /api/todos/:id/done
    removeTodo(id)                → optimistic del  → DELETE /api/todos/:id
  On API failure: reverts to previous state + sets error message
```

## 🔀 Monorepo & npm Workspaces

The root `package.json` declares both sub-packages as workspaces:

```json
{
  "name": "taska",
  "private": true,
  "workspaces": ["Backend", "FrontEnd/client"]
}
```

This lets you install all dependencies from the repo root with a single `npm install`, and run scripts across workspaces without `cd`-ing into each folder. Shared packages are hoisted to the root `node_modules/` automatically.

## 📋 Frontend Architecture Decisions

| Decision | Rationale |
|---|---|
| **Vite over CRA** | Significantly faster HMR and build times; first-class TypeScript support |
| **Centralized API layer** (`api/todos.js`) | All HTTP logic in one file — easy to swap base URLs, easy to explain in a code walkthrough |
| **`useTodos` custom hook** | Keeps components pure and presentation-focused; all async logic is testable in isolation |
| **Optimistic updates** | UI feels instant even on slow connections; rollback on failure keeps data consistent |
| **CSS Modules** | Scoped styles per component — no class name collisions, no runtime overhead |
| **`react-hot-toast`** | Lightweight (< 5 KB), zero-config notifications that replace noisy alert dialogs |

---

## 📋 Backend Architecture Decisions

| Decision | Rationale |
|---|---|
| **Express Router** | Keeps route definitions separate from app bootstrap; easy to extend with new resource types |
| **Mongoose** (`timestamps: true`) | Schema validation, `maxlength` on title, and automatic timestamp fields with zero boilerplate |
| **`morgan`** | HTTP request logging in development — makes debugging significantly faster |
| **`cors`** | Allows the Vite dev server (port 5173) to call the API server (port 5000) without browser errors |
| **Global error handler** | One place to format and log all thrown errors — consistent JSON error shape throughout |
| **`200` on DELETE** (not `204`) | Returns a `{ message }` body, which is easier for Axios to handle and log on the frontend |
